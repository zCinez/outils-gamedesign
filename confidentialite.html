3. Stockage local et cloud

L’outil utilise le stockage du navigateur, notamment localStorage, sessionStorage et IndexedDB, pour des données de travail et des sessions. La synchronisation cloud n’élimine pas ces copies locales. Effacer les données du site peut faire perdre les changements non synchronisés ; cela ne supprime pas automatiquement les copies cloud.

Le code intègre Supabase pour l’authentification et la synchronisation, ainsi qu’une fonction distante dédiée aux CDC utilisant Turso. Leur activation et leur configuration dépendent du déploiement. Un indicateur « Local » ne signifie pas nécessairement qu’aucune requête réseau n’est effectuée.

4. Destinataires et services externes

Les membres autorisés de l’espace partagé et les prestataires techniques nécessaires au service peuvent traiter les données concernées. Les fournisseurs identifiés dans le code comprennent Supabase, Turso et jsDelivr pour certaines bibliothèques. Lorsque le site est publié sur GitHub Pages, GitHub assure l’hébergement des fichiers du site.

Les images ou autres ressources chargées par une URL externe sollicitent leur hébergeur. Ne fournis pas de lien privé ou sensible. La liste contractuelle des prestataires, leurs régions de traitement et les éventuelles garanties de transfert doivent être confirmées par l’éditeur.

5. Conservation

Les données locales peuvent persister jusqu’à leur suppression dans l’outil ou le navigateur, ou leur éviction par celui-ci. Aucune durée générale d’expiration des documents cloud n’a été identifiée dans le code examiné. Les délais de suppression, de journalisation et de conservation des sauvegardes doivent être fixés et indiqués ici par l’éditeur.
